## 2. 프로젝트 개요

My Health Log는 대상자가 체중, 혈압, 혈당, 걸음 수, 수면 시간 등의 건강 정보를 기록하고 관리하는 웹 서비스이다.

대상자는 자신의 건강 기록을 직접 관리할 수 있으며, 보호자는 대상자의 승인을 받은 후 해당 대상자의 건강 기록에 접근할 수 있다. 관리자는 전체 사용자와 대상자의 건강 기록을 조회하고 관리한다.

서비스는 역할별 데이터 접근 권한을 FastAPI에서 검증하고, Streamlit을 통해 실제 사용자가 이용할 수 있는 화면을 제공한다.

---

## 3. 프로젝트 배경

개인의 건강 정보는 체중, 혈압, 혈당, 걸음 수, 수면 시간 등 여러 항목으로 나뉘어 관리된다. 그러나 수치를 단순히 저장하는 것만으로는 현재 건강 상태와 변화 추이를 직관적으로 파악하기 어렵다.

또한 건강 관리가 필요한 대상자는 보호자나 간병인의 도움을 받을 수 있다. 이때 대상자의 동의 없이 다른 사용자가 건강 정보에 접근하지 못하도록 역할과 권한을 분리해야 한다.

My Health Log는 다음 문제를 해결하는 것을 목표로 한다.

- 여러 건강 지표를 하나의 서비스에서 기록
- 건강 수치를 자동으로 계산하고 분류
- 최근 건강 기록의 변화 추이를 시각화
- 보호자와 대상자의 승인 기반 연결
- 사용자 역할에 따른 데이터 접근 제한
- Docker 기반 로컬 실행 및 AWS 서버 배포

---

## 4. 프로젝트 목표

### 4.1 핵심 목표

대상자가 자신의 건강 기록을 안전하게 관리하고, 승인된 보호자와 관리자가 역할별 권한에 따라 필요한 건강 정보에 접근할 수 있는 서비스를 구현한다.

### 4.2 세부 목표

- 건강 기록 생성, 조회, 수정, 삭제 기능 구현
- JWT 기반 회원가입 및 로그인 구현
- 대상자, 보호자, 관리자 역할 분리
- 보호자 연결 요청 및 대상자 승인 기능 구현
- 역할별 건강 기록 접근 권한 적용
- BMI와 건강 상태 자동 분석
- 평균 통계 및 최근 7일 추이 제공
- 최근 7일과 직전 7일 비교 리포트 제공
- 잘못된 건강 수치와 미래 날짜 저장 차단
- Streamlit 기반 사용자 화면 제공
- Docker Compose 및 AWS Lightsail 배포

## 5. 사용자 유형

### 5.1 대상자

자신의 건강 정보를 직접 기록하고 관리하는 사용자이다.

#### 주요 기능

- 회원가입 및 로그인
- 대상자 연결 코드 확인
- 본인의 건강 기록 입력
- 본인의 건강 기록 조회, 수정, 삭제
- 기간별 건강 기록 검색
- 건강 통계 확인
- 최근 7일 건강 추이 확인
- 주간 리포트 확인
- 보호자 연결 요청 승인 또는 거절

---

### 5.2 보호자

대상자의 승인을 받은 후 건강 기록을 함께 관리하는 사용자이다.

#### 주요 기능

- 회원가입 및 로그인
- 대상자 코드로 연결 요청
- 연결 요청 상태 확인
- 승인된 대상자 목록 조회
- 승인된 대상자의 건강 기록 입력
- 승인된 대상자의 건강 기록 조회, 수정, 삭제
- 승인된 대상자의 통계 및 주간 리포트 확인

보호자는 승인되지 않은 대상자의 정보에 접근할 수 없다.

---

### 5.3 관리자

서비스 전체 사용자와 건강 기록을 관리하는 운영 사용자이다.

#### 주요 기능

- 관리자 계정 로그인
- 전체 사용자 목록 조회
- 전체 대상자 목록 조회
- 모든 대상자의 건강 기록 조회
- 대상자별 건강 기록 입력, 수정, 삭제
- 대상자별 건강 통계 및 주간 리포트 조회
- 보호자 연결 요청 조회 및 상태 처리

관리자 계정은 일반 회원가입 화면에서 생성하지 않으며, 서버 명령을 통해 별도로 생성한다.

## 6. 핵심 사용자 흐름

### 6.1 대상자 가입 및 건강 기록 입력

```text
대상자 회원가입
→ 로그인
→ 대상자 연결 코드 발급
→ 건강 기록 입력
→ 건강 상태 자동 분석
→ 기록·통계·그래프·주간 리포트 확인
```

### 6.2 보호자 연결

```text
보호자 회원가입
→ 로그인
→ 대상자에게 받은 연결 코드 입력
→ 연결 요청 생성
→ 대상자가 요청 승인
→ 보호자가 대상자의 건강 기록에 접근
```

### 6.3 관리자 이용

```text
서버에서 관리자 계정 생성
→ 관리자 로그인
→ 전체 사용자와 대상자 조회
→ 대상자별 건강 기록 및 통계 관리
```

## 7. 기능 요구사항

### FR-01 회원가입

사용자는 이메일, 비밀번호, 이름, 역할을 입력해 가입한다.

#### 조건

- 이메일은 중복될 수 없다.
- 비밀번호는 8자 이상이어야 한다.
- 일반 회원가입에서 선택할 수 있는 역할은 대상자와 보호자이다.
- 대상자 가입 시 고유한 연결 코드가 발급된다.
- 보호자 계정에는 대상자 연결 코드가 발급되지 않는다.
- 관리자 계정은 일반 회원가입으로 생성할 수 없다.

---

### FR-02 로그인

사용자는 이메일과 비밀번호로 로그인한다.

#### 결과

- 로그인 성공 시 JWT 액세스 토큰을 발급한다.
- 이후 API 요청은 Bearer 토큰을 사용한다.
- 로그인 사용자의 역할에 따라 메뉴와 접근 가능한 데이터가 달라진다.
- 로그인 실패 시 인증 오류를 반환한다.

---

### FR-03 건강 기록 입력

사용자는 권한이 있는 대상자의 건강 기록을 입력한다.

#### 입력 항목

- 기록 날짜
- 체중
- 키
- 수축기 혈압
- 이완기 혈압
- 공복 혈당
- 걸음 수
- 수면 시간
- 메모

#### 자동 계산 및 분류

- BMI 계산
- BMI 상태 분류
- 혈압 상태 분류
- 혈당 상태 분류
- 걸음 수 등급 계산
- 건강 경고 생성

#### 저장 정보

- 건강 기록 대상자 ID
- 실제 기록 작성자 ID
- 입력 건강 수치
- 자동 계산 및 분류 결과
- 생성·수정 시각

---

### FR-04 건강 기록 조회

사용자는 권한 범위에 있는 건강 기록을 조회한다.

#### 조회 방식

- 접근 가능한 전체 기록 조회
- 대상자별 기록 조회
- 기간별 검색
- 기록 ID를 이용한 단건 조회

#### 권한

- 대상자: 본인 기록만 조회
- 보호자: 연결이 승인된 대상자 기록만 조회
- 관리자: 모든 대상자 기록 조회

---

### FR-05 건강 기록 수정 및 삭제

사용자는 권한이 있는 건강 기록을 수정하거나 삭제한다.

#### 조건

- 기록 수정 시 BMI와 건강 상태 분류를 다시 계산한다.
- 기록 대상자 ID를 다른 사용자로 변경할 수 없다.
- 권한이 없는 기록의 수정 및 삭제는 차단한다.

---

### FR-06 보호자 연결 요청

보호자는 대상자가 전달한 연결 코드를 입력해 연결을 요청한다.

#### 처리 과정

- 보호자 역할만 연결 요청 가능
- 유효한 대상자 코드인지 확인
- 동일한 보호자와 대상자의 중복 요청 차단
- 최초 연결 상태는 `pending`
- 대상자 또는 관리자가 승인·거절 처리

#### 연결 상태

| 상태 | 설명 |
|---|---|
| `pending` | 대상자 승인을 기다리는 상태 |
| `approved` | 대상자가 연결을 승인한 상태 |
| `rejected` | 대상자가 연결을 거절한 상태 |

---

### FR-07 접근 가능한 대상자 목록

사용자는 역할에 따라 접근 가능한 대상자 목록을 조회한다.

| 역할 | 조회 결과 |
|---|---|
| 대상자 | 본인 |
| 보호자 | 연결이 승인된 대상자 |
| 관리자 | 전체 대상자 |

Streamlit 화면의 대상자 선택 메뉴는 이 목록을 사용한다.

---

### FR-08 건강 통계

선택한 대상자의 건강 기록 평균을 제공한다.

#### 사용자 화면 표시 지표

- 기록 수
- 평균 BMI
- 평균 수축기 혈압
- 평균 이완기 혈압
- 평균 혈당
- 평균 걸음 수
- 평균 수면 시간

평균 체중은 사용자에게 유의미하지 않은 단순 평균값으로 판단하여 통계 화면에서 제외한다.

---

### FR-09 최근 7일 건강 추이

오늘을 포함한 최근 7일간의 건강 기록을 그래프로 표시한다.

#### 그래프 항목

- 체중 및 BMI
- 수축기·이완기 혈압
- 혈당
- 걸음 수
- 수면 시간

#### 표시 규칙

- 기록이 한 건이면 막대그래프로 표시
- 기록이 두 건 이상이면 선 그래프로 표시
- 같은 날짜에 여러 기록이 있으면 날짜별 평균 사용
- 최근 7일 기록이 없으면 안내 메시지 표시

---

### FR-10 주간 리포트

선택한 종료일을 기준으로 최근 7일과 직전 7일의 건강 기록을 비교한다.

#### 표시 내용

- 주요 지표 카드
- 최근 7일 데이터
- 직전 7일 데이터
- 기간별 변화량
- 사용자용 요약 화면
- 원본 리포트 데이터 확장 보기

주간 리포트 종료일은 오늘 이후로 지정할 수 없다.

---

### FR-11 관리자 사용자 조회

관리자는 전체 사용자 목록을 조회한다.

#### 표시 정보

- 사용자 ID
- 이메일
- 이름
- 역할
- 계정 활성 상태
- 대상자 연결 코드
- 가입 일시

대상자와 보호자는 전체 사용자 목록에 접근할 수 없다.

## 8. 입력값 검증

| 항목 | 최소값 | 최대값 | 추가 조건 |
|---|---:|---:|---|
| 기록 날짜 | - | 오늘 | 미래 날짜 불가 |
| 체중 | 20kg | 300kg | - |
| 키 | 50cm | 250cm | - |
| 수축기 혈압 | 60 | 250 | 이완기 혈압보다 높아야 함 |
| 이완기 혈압 | 30 | 150 | 수축기 혈압보다 낮아야 함 |
| 공복 혈당 | 40 | 500mg/dL | - |
| 걸음 수 | 0 | 100,000 | 음수 불가 |
| 수면 시간 | 0시간 | 24시간 | - |
| 메모 | - | 500자 | 선택 입력 |

검증은 두 단계로 수행한다.

1. Streamlit에서 입력값을 확인해 잘못된 API 요청을 1차 차단한다.
2. FastAPI의 Pydantic 스키마에서 요청을 다시 검증해 잘못된 데이터가 DB에 저장되지 않도록 2차 차단한다.

## 10. 비기능 요구사항

### 10.1 보안

- 비밀번호는 평문으로 저장하지 않는다.
- 비밀번호를 해시 처리한 후 데이터베이스에 저장한다.
- 인증에는 JWT를 사용한다.
- API에서 사용자 역할과 연결 승인 상태를 검증한다.
- `.env` 파일은 Git 저장소에 업로드하지 않는다.
- JWT 비밀키와 DB 비밀번호는 환경변수로 관리한다.
- 관리자 계정은 서버 명령을 통해서만 생성한다.

### 10.2 사용성

- 하늘색과 흰색 기반의 클라우드 테마 적용
- 역할별 사이드바 메뉴 제공
- 선택된 메뉴를 색상으로 강조
- 카드형 건강 통계 제공
- 건강 기록을 표와 그래프로 시각화
- 주간 리포트를 일반 사용자가 이해하기 쉬운 형태로 제공
- 입력 오류를 화면에 명확하게 표시

### 10.3 운영 및 배포

- Docker Compose를 이용해 API, DB, 프런트엔드를 함께 실행한다.
- PostgreSQL 데이터는 Docker 볼륨으로 유지한다.
- AWS Lightsail Ubuntu 인스턴스에 배포한다.
- Streamlit과 FastAPI를 외부 포트로 공개한다.

## 13. 데이터베이스 구성

### 13.1 `users`

대상자, 보호자, 관리자 계정을 저장한다.

### 13.2 `guardian_patient_links`

보호자와 대상자의 연결 관계와 승인 상태를 저장한다.

### 13.3 `health_records`

건강 측정값, 자동 계산 결과, 건강 분류와 경고를 저장한다.

`health_records.user_id`는 건강 기록의 대상자를 의미하고, `health_records.created_by_user_id`는 실제로 기록을 입력한 사용자를 의미한다.

## 16. 테스트 기준

### 인증 및 사용자

- 대상자 회원가입 및 로그인
- 보호자 회원가입 및 로그인
- 관리자 로그인
- 중복 이메일 가입 차단
- 잘못된 비밀번호 로그인 차단

### 건강 기록

- 건강 기록 생성·조회·수정·삭제
- 미래 날짜 저장 차단
- 건강 수치 최소·최대 범위 검증
- 수축기 혈압과 이완기 혈압 관계 검증
- BMI 및 건강 분류 자동 계산

### 역할 및 권한

- 대상자의 타 사용자 기록 접근 차단
- 보호자의 승인되지 않은 대상자 접근 차단
- 관리자의 전체 사용자 및 대상자 조회
- 일반 사용자의 관리자 메뉴 접근 차단

### 보호자 연결

- 대상자 코드 발급
- 보호자 연결 요청
- 대상자 승인·거절
- 중복 연결 요청 차단
- 승인 후 대상자 기록 접근

### 통계 및 시각화

- 대상자별 평균 통계
- 최근 7일 그래프
- 기록 한 건일 때 막대그래프 표시
- 기록 두 건 이상일 때 선 그래프 표시
- 최근 7일과 직전 7일 비교 리포트

### 배포

- Docker Compose 전체 서비스 실행
- AWS Streamlit 주소 접속
- AWS Swagger 주소 접속
- PostgreSQL 데이터 볼륨 유지

## 17. 완료 기준

- 대상자, 보호자, 관리자 계정으로 로그인할 수 있다.
- 역할에 따라 접근 가능한 사용자와 건강 기록이 분리된다.
- 건강 기록 CRUD가 정상 작동한다.
- 범위를 벗어난 건강 수치가 저장되지 않는다.
- 미래 날짜 기록이 저장되지 않는다.
- 보호자 연결 요청과 승인이 정상 작동한다.
- 건강 통계와 최근 7일 그래프가 표시된다.
- 최근 7일과 직전 7일 비교 리포트가 표시된다.
- Docker Compose에서 API, DB, 프런트엔드가 실행된다.
- AWS Lightsail 배포 주소에서 서비스에 접속할 수 있다.
